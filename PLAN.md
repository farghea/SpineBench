Download status is in `TO_DOWNLOAD.md`, theses are in `DISSERTATIONS.md`, and the changelog is `CHANGES.md`. **Every pass rule in this file is a template.** It is marked `template` and runs only as `provisional` until its target numbers are extracted from the full text and frozen (§5, rule 2). No threshold here is a literature value.

## 1. What SpineBench is

SpineBench is a set of validation tests for computational models of the thoracic and lumbar spine: musculoskeletal (MSK) and finite element (FE). It has three layers.

1. **INPUTS** (standardised, never graded). The kinematics, masses and anthropometry needed to drive a model. Every model runs the outcome tests with the same default inputs, so a difference in results comes from the model, not from posture or mass assumptions. A robustness rule (IR) reruns graded tests under alternative published inputs.
2. **MODEL-PROPERTY CHECKS** (graded, run before any task). Does the model contain plausible muscles, passive tissues, joints and masses? A model can pass an outcome test for the wrong reason, for example a moment arm that is too large cancelled by a CSA that is too small. Property checks catch this.
3. **OUTCOME TESTS** (graded). In vivo responses for MSK models and in vitro responses for FE models.

Reports show the three layers separately. Outcome results of a model that fails a property check are still reported, flagged `property-fail`. Property-layer data are the normal calibration sources. A model that was tuned to a property dataset is tagged `calibration` for that check (§5, rule 6).

Suite code prefixes: **IN** = input, **IR** = robustness rule, **PC** = property check, **M** = MSK outcome (in vivo), **F** = FE outcome (in vitro). The old M8 (kinematic library) is now IN1/IN2 and the old M9 (sensitivity) is now IR. The old F0 (tissue gate) is split into PC3 (ligaments) and PC4 (disc). FSU stiffness matrices moved from F5 to PC6. F5 keeps multi-segment compression and buckling.

## 5. Rules (all layers)

1. **Tolerances fixed in advance.** Metric and threshold are written in the protocol file before any model result is seen. They change only with a new SpineBench version and a changelog line.
2. **Templates are not tolerances.** A threshold stays `template` until its targets are extracted from the full text. Template runs are reported as `provisional`, not PASS/FAIL.
3. **Robustness rule (IR).** Every graded outcome test runs with the default inputs and at least two alternative published input sets (§2, IR). A result is `robust PASS` only if it passes under all of them. Flips are reported as `input-sensitive`.
4. **One protocol file per test** (`<suite>-<nn>.yaml`). It holds: specimen or subject, structures present, BCs, load steps, control mode, outputs and how they are sampled, target, pass rule, and reference model run. Property tests (PC4, PC5) must replicate the specimen geometry and grips.
5. **Provenance on every number.** Each number carries: paper uid, DOI, table or figure, extraction method (table / text / digitised), who extracted it and when, and status (`verified` / `[verify]` / `secondary`). `secondary` means taken from a re-plot (own papers for IDP, Dreischarf2014 Fig 2, LiebschWilke2022 or Watt2022 for dropped Spine papers). A `[verify]` value cannot act as a gate.
6. **Calibration vs validation kept apart.** A dataset used to tune a model is tagged `calibration` for that model and excluded from its score. Property data are the usual calibration sources; outcome data must not be.
7. **Report everything.** Raw prediction, error, z (where an SD exists) and grade for every test. Failures are listed, not hidden.
8. **Frozen releases** ship with a manifest: test list, protocol hashes, data hashes, and reference model and solver versions.
9. **Covered by own papers.** In vivo IDP from Wilke 1999, Sato 1999, Takahashi 2006 and Polga 2004, and the flexion–relaxation data of McGill & Kippers 1994, enter through the user's own papers. They are tagged `secondary`, with the own-paper figure as their location (Appendix A). The Polga 2004 and McGill & Kippers 1994 locations have not been found yet.
10. **Spine (LWW) papers that cannot be accessed now** are replaced by accessible equivalents where possible (TO_DOWNLOAD.md §C). Any value still needed from them is `secondary`.

## 7. Explicit gaps

- **Thoracic in vivo IDP** is still one study (Polga 2004, P08). No own paper was found that reports it (Appendix A). The only other source is Meir2007, which is intraoperative and scoliotic (tier 3).
- **No thoracic facet-force data** in vitro. F7 is lumbar only.
- **Thoracic in vivo rotation per level** comes from Fujimori2012 (Spine). Its per-level values are printed in the PubMed abstract, so they are usable as `secondary` without the full text.
- **Thoracic EMG during axial rotation:** no accessible dataset was found. Lee2005 is Spine; Lee2011 and Lee2009 cover other tasks.
- **No single T1–S1 in vitro study** under pure moments. Orbach2023 (T1-L5 with rib cage) comes closest.
- **Per-level trunk mass** rests on small samples (Pearsall1996, n = 4; Pearsall1994, MRI males). Erdmann1997 (n = 15) is a check.
- **Successive reduction (M7)** has no measured ground truth for stability. Only its EMG and solvability consequences are graded.
- **Ligament datasets in Naserkhaki2018:** only 4 of the 8 are confirmed so far (Chazal 1985; the Shirazi-Adl 1986 synopsis; White & Panjabi 1990; Nolte 1990 via Schmidt2007). Read its table when the PDF arrives.
